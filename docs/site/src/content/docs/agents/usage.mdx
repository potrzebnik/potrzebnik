## What lives under `.claude/`

<RepoFile path=".claude" /> holds agents and a command scoped to this
repository, loaded automatically whenever Claude Code runs from the project
root. This page explains what they're for and when to reach for them; the [Agent
& skill index](/potrzebnik/agents/index-generated/) lists what's defined right
now.

Skills live one level up, in <RepoFile path=".agents/skills" />: a shared location several
agentic tools can read directly, so a `SKILL.md` written once doesn't need copying per tool.
`.claude/skills` is a symlink to it, kept because Claude Code only looks under `.claude/skills/`.
Add new skills under `.agents/skills/<name>/SKILL.md`.

## Reviewer agents

Two agents under <RepoFile path=".claude/agents" /> read a diff and return structured findings.
Pick the general one for backend, config, or cross-cutting changes, and the frontend-aware one for
anything under <RepoFile path="src/app" />, <RepoFile path="src/components" />, Storybook stories, or the design-token file <RepoFile path="src/app/theme.css" />, where it enforces conventions distilled from past PR review history.

Only frontend-reviewer is read-only by construction: its frontmatter pins `tools: Read, Grep,
Glob, Bash`, so it cannot edit. code-reviewer declares no `tools` key and therefore inherits the
full toolset, including `Edit` and `Write`; its read-only behaviour is a convention its prompt
asks for, not a guarantee the harness enforces.

Invoke either directly through the `Agent` tool, or trigger by describing the task in natural
language and let the matching agent's description pick it up:

```text
Review the open pull request with the frontend-reviewer
code-reviewer: review the diff against main
```

For a mixed change, split the request explicitly:

```text
Review the current branch: code-reviewer for backend files, frontend-reviewer for src/app and src/components
```

Both agents emit findings as severity-ranked YAML (blocker / major / nit), each with a file,
lines, rationale, and a fix proposal.

## The `mentor-review` command

<RepoFile path=".claude/commands/mentor-review.md" /> orchestrates both reviewer
agents in parallel against `git diff main...HEAD` plus uncommitted changes, then
presents each finding as a teaching card: concept, why it matters, impact, the
offending code, the fix, and references. Reach for it before opening a pull
request, not as a replacement for a human reviewer.

Two modes:

- Informative: prints every finding as a teaching card, makes no edits.
- Interactive fix mode: walks findings one at a time; accepting one spawns a sub-agent that
  applies the fix and shows the resulting diff before moving to the next finding.

Findings are session-scoped: nothing is written to disk, so there's no report file to clean up
afterward.

## The architecture-regeneration skill

<RepoFile path=".agents/skills/regenerate-architecture-page" /> rewrites the
[Architecture](/potrzebnik/architecture/) page and its diagram from the current
shape of the repository. Run it by hand whenever a change reshapes the codebase
enough that the diagram or its prose would go stale; it is deliberately not
wired into the docs build, so the resulting diff lands in the same pull request
as the change that prompted it.

## The documentation skills

Two skills keep the prose in this repository honest, and they divide the work between them.

<RepoFile path=".agents/skills/writing-for-agents" /> is the reference for _how_
to write anything an agent consumes — a skill, an agent definition, `CLAUDE.md`,
a docs page. Read it before adding or editing one of those.
<RepoFile path=".agents/skills/audit-docs" /> is the check on whether what is
already written is still _true_: it takes the checkable claims out of the prose,
settles each one against the repository, fixes what has objectively drifted and
brings the rest to you before touching it.

They deliberately skip what the build already guards. A `<RepoFile>` path that does not exist throws
during the docs build, and a broken link between pages fails link validation, so neither is worth an
audit pass.

## Adding a new agent

Create a new file under <RepoFile path=".claude/agents" /> with `name`, `description`, and
optionally `tools` in its frontmatter, and a system prompt as the body. Commit it; it becomes
available on the next Claude Code session, and the next docs build picks it up in the generated
index automatically.
